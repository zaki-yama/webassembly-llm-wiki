# FP16

**Phase 2(仕様文面あり)** / Champion: Brendan Dahl

> 2026-08-04〜05のCG対面会合(Siemens主催)で "Half Precision"(champion: Ilya Rezvov)から改名され、championもBrendan Dahlに交代の上、Phase 1からPhase 2に昇格した([CG-2026-08.md](https://github.com/WebAssembly/meetings/blob/main/main/2026/CG-2026-08.md)、[proposals#237](https://github.com/WebAssembly/proposals/commit/400fcd9641a0e70f2f00b6fcf4ea5fcebe76b754))。リポジトリ名は `WebAssembly/half-precision` のまま。

## 一言でいうと

半精度浮動小数点数(IEEE754-2008 binary16、`f16`)をSIMDレーン型として追加し、メモリ/計算帯域を節約するproposal。

## なぜ必要か(Motivation)

Web上のグラフィックスやAI推論では、半精度浮動小数点を使うことでメモリ帯域・ストレージ容量・演算速度のボトルネックを緩和できる。IntelのF16C/AVX512-FP16、ArmのARMv8.2 FP16算術拡張(Pixel 3、Galaxy S9/S10、iPhone A11以降、Apple Silicon Mac、Snapdragon 850以降のWindows ARM64機など)といった形でハードウェアサポートが既に広く存在しており、Wasmからそれを直接利用できるようにする。

## 仕組み

出典: [Overview.md](https://github.com/WebAssembly/half-precision/blob/c29bdf39fc848b4f6f3eeb42e4be8c027f7f0d8a/proposals/half-precision/Overview.md)

| 要素 | 説明 |
|---|---|
| `f16x8` レーン形状 | 新しいSIMD `v128` のレーン解釈。各レーンはIEEE binary16の `f16` |
| メモリ命令 | `f32.load_f16` / `f32.store_f16` — メモリ上のf16値をf32として読み書き(f16自体は第一級のスカラー値型ではない) |
| レーン操作 | `f16x8.splat` / `extract_lane` / `replace_lane`(JS境界とはf32でやり取り) |
| 比較・単項・二項演算 | `eq`/`ne`/`lt`/`gt`/`le`/`ge`、`abs`/`neg`/`sqrt`/`ceil`/`floor`/`trunc`/`nearest`、`add`/`sub`/`mul`/`div`/`min`/`max`/`pmin`/`pmax` — f32/f64の対応命令と同じ意味論を踏襲 |
| 変換 | `i16x8.trunc_sat_f16x8_{s,u}` / `f16x8.convert_i16x8_{s,u}` / `f16x8.demote_{f32x4,f64x2}_zero` / `f32x4.promote_low_f16x8` / `i16x8.trunc_f16x8_{s,u}` |
| FMA | `f16x8.madd` / `f16x8.nmadd` |
| 丸め | すべての演算はデフォルトの *roundTiesToZero* を使用し、NaN伝播・デフォルトNaN値の扱いは既存の浮動小数点演算に合わせる |

命令は `0xFC`(メモリ命令2個)と `0xFD`(SIMD命令群、`0x120`〜)のプレフィックス配下に割り当てられる。f16はJSとの境界では第一級の値型ではないため(i8/i16と同様)、JS↔Wasm変換は定義不要。

## 例

```wat
;; メモリからf16を読み、f32として扱う
(func $load_half (param $addr i32) (result f32)
  (f32.load_f16 (local.get $addr)))

;; f16x8ベクトルの加算
(func $add_f16x8 (param $a v128) (param $b v128) (result v128)
  (f16x8.add (local.get $a) (local.get $b)))
```

## 経緯と現状

- リポジトリ(`WebAssembly/half-precision`)自体はリネームされておらず、README・proposals一覧上の表示名のみ "FP16" に変更された
- CGの2026-08対面会合では新しい命令の調整とベンチマークデータの提示を伴うアップデートが予定されていた(議事録の会議メモ本文は本執筆時点で "TBD" のまま未記入)
