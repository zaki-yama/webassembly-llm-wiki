# WebAssembly Weekly 2026-W36 (8/31〜9/6)

## 今週のハイライト

proposalのフェーズ移行はなし。今週最大の動きは[[component-model-overview|Component Model]]の**キャンセレーション配送モデルの簡素化**([#716](https://github.com/WebAssembly/component-model/commit/8892da0)): `waitable-set.wait`/`poll`や`thread.*`系組み込みから`cancellable`免除引数を全廃し、`task-cancelled`イベントの配送先をstackless `callback` ABIの関数に一本化した(stackful ABI向けの配送は将来課題として明記)。あわせて値型に`map`・固定長list(`fixed-length list`)のエンコーディングが新規定義された([#712](https://github.com/WebAssembly/component-model/commit/a70dae6))。次回CG 2026-09-22の議題には[[acquire-release-atomics]]のPhase 3投票が予定されており、来週以降の注目点。

## フェーズ移行・proposal動向

- proposalsリポジトリ(README.md / finished-proposals.md)に変化なし。フェーズ移行は今週なし
- [[extended-name-section]]: Overview.mdに**parameter names**(id 12)・**tag parameter names**(id 13)サブセクションを追加。テキスト形式の`@name`アノテーションがラベル・テーブル・メモリ・グローバル・elem/data segmentの全てで使えることも明記された([commit](https://github.com/WebAssembly/extended-name-section/commit/ab1d65a))。Phase 2のまま
- [[custom-descriptors]]: `descriptor`/`describes`のサブタイピング規則に、**両者のfinality(final/open)が一致していなければならない**という制約を追加([#112](https://github.com/WebAssembly/custom-descriptors/commit/e9f7a93)、issue #61をクローズ)。不一致だと非final側にsubtypeが作れなくなるための整合性要件
- 他の個別proposalリポジトリ(threads・js-promise-integration・esm-integration・wide-arithmetic・stack-switching・acquire-release-atomics等)はいずれも直近チェック時点から差分なし

## WASI / Component Model

- [[component-model-overview]]: 上記ハイライトの通り、キャンセレーション配送モデルの簡素化と`map`/固定長listのエンコーディング追加が中心。あわせてCanonical interface nameのバージョン正規化規則を調整([#711](https://github.com/WebAssembly/component-model/commit/cfc0266)): build metadata(`+foo`)は常にsemversuffixとして分離、pre-release版(`-alpha`等)は分割しない仕様に変更。`thread.*-then-promote`系組み込みで対象スレッドが呼び出し元自身の場合はトラップと明確化([#687](https://github.com/WebAssembly/component-model/commit/7c67611))
- WASI: v0.3.1が現行(新リリースなし、次回0.3.2は10/13予定)。今週の変化はchampion一覧の更新のみ(上記ミーティング節参照)
